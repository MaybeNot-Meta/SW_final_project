# 사용자 경험 개선 및 경험 꺼내기 수동 태그 설정

대상: `SW_final_project_clean_4fixes_mypage_spacing.zip`을 기준으로 한 증분 변경입니다.

## 보존 원칙

- 기존 4가지 연동 수정(유형 2 이동, 경험 → 직무, 기록 → 프로젝트, STAR 이동)은 유지합니다.
- 공통 저장 API·저장 키(`user`, `records`, `projects`, `scraps`), 공통 헤더, 마이페이지의 24px 여백, 포트폴리오/경험 채우기 화면을 교체하지 않았습니다.
- 기존 HTML ID, 각 기록 작성 템플릿(STAR/KPT/자유), 검색·필터·정렬, 캘린더·스트릭, 직무 계산식, 포트폴리오 묶기/STAR 작업은 유지합니다.

## 실제 변경

1. **온보딩 유형 2 안내** (`index.html`, `js/home.js`): 기존의 저장·이동 로직은 그대로 두고, 유형 2의 프로필 버튼 문구를 `저장하고 경험 꺼내기`, 건너뛰기를 `건너뛰고 경험 꺼내기`로 표시합니다. 유형 1은 기존 문구를 사용합니다.
2. **경험 꺼내기 수동 역량 태그** (`modules/record/index.html`, `modules/record/script.js`, `modules/record/styles.css`): 경험 카드마다 공통 역량 태그 9개를 체크박스형 칩으로 표시합니다. 답변 입력 시 추천 태그가 처음 선택되지만 사용자가 자유롭게 변경할 수 있고, 직접 선택한 뒤에는 자동 추천이 덮어쓰지 않습니다. 작성한 경험 **3개 이상 + 각 경험마다 태그 1개 이상**이면 직무 매칭 버튼이 활성화됩니다. 선택한 태그 그대로 `records`에 저장되어 직무 매칭에 반영됩니다. 이미 저장된 경험의 내용·태그 편집은 기존 ID로 저장하여 프로젝트 연결을 보호합니다. 기록 목록에서 수정·삭제한 경험은 경험 꺼내기 화면의 임시 캐시에도 반영합니다.
3. **기록 삭제 실수 방지** (`modules/record/script.js`): 휴지통을 누르면 제목과 복구 불가·프로젝트 참조 해제를 설명한 확인창이 뜹니다. 취소하면 저장소를 변경하지 않습니다. 편집·삭제 아이콘에는 툴팁을 추가했습니다.
4. **직무 매칭률 근거** (`modules/job/job-connection.js`): 태그와 필요 역량을 비교한 **참고 점수**임을 설명합니다. 계산 알고리즘과 레이더 차트는 그대로 유지합니다.
5. **프로젝트 묶기 결과 안내** (`portfolio/js/projects.js`, `portfolio/css/portfolio.css`): 기록 목록에서 프로젝트를 만들면 원래 프로젝트 화면으로 이동하고 강조 표시 및 제목을 직접 수정할 수 있다는 안내가 나타납니다. 프로젝트 저장/수정 동작은 변경하지 않았습니다.
6. **기록 임시저장 상태** (`modules/record/index.html`, `modules/record/script.js`): 처음에는 `임시저장 전`, 변경하면 `작성 중 · 미저장`, 임시저장에 성공하면 `임시저장 완료`, 새로고침 후에는 `임시저장본 불러옴`으로 표시됩니다. 제목, 템플릿 내용, 선택한 **모든** 태그와 편집 중인 기록 ID를 복원합니다. `새 기록` 버튼은 이전 기록을 덮어쓰지 않도록 편집 상태를 해제합니다.
7. **보조 텍스트 가독성** (`common/tokens.css`): `--color-text-muted`를 `#9AA4B8` → `#66758E`로 바꿨습니다. 흰 배경 대비는 약 2.51:1 → 4.67:1입니다. 브랜드색, 레이아웃, 공통 기능 코드는 유지합니다.

## 자동 검사

```bash
node tests/regression-fixes.cjs
node tests/regression-ux.cjs
```

추가로 전체 JS `node --check`, 13개 HTML에서 로컬 파일 참조 경로 확인, 원본 ZIP 대비 변경 파일 검사 실행.

**제한:** 이 환경에서는 로컬 주소·파일 주소·data 주소의 브라우저 탐색이 보안 정책으로 차단되어 Chromium 실제 클릭 테스트를 완료하지 못했습니다. 따라서 실행 환경의 브라우저에서 아래 회귀 테스트를 확인해야 합니다. 사용자의 실제 기록 데이터가 있는 브라우저에서는 초기화/샘플 덮어쓰기 테스트를 하지 마세요.

## Live Server 브라우저 회귀 테스트

기존 로컬 저장소를 **백업**하고 별도 브라우저 프로필(또는 시크릿 창)에서 테스트하세요.

- [ ] 유형 1: 닉네임, 유형 선택, 관심 태그 2~3개, 프로필 저장/건너뛰기, 홈 진입, 마이페이지 변경 정상
- [ ] 유형 2: 프로필 버튼에 `경험 꺼내기` 안내 표시 → 건너뛰기/저장 후 경험 꺼내기 자동 진입
- [ ] 경험 1~3개 텍스트 작성: 추천 칩 표시, 선택·해제·추가 가능, 선택 개수와 직무 매칭 활성화 조건이 정확함
- [ ] 카테고리 변경·재방문: 작성 중인 답변과 태그가 보존됨 (같은 페이지 내), 이전 저장 경험을 수정해도 중복 생성 안 됨
- [ ] 직무 매칭: 선택한 태그가 저장된 경험과 내 역량 프로필, 부족 역량 분석에 반영됨
- [ ] 기록 목록: 검색, 필터, 정렬, 기록 상세·수정·저장, 삭제 취소 시 데이터 보존, 삭제 확인 시 정상 삭제
- [ ] 기록 작성: STAR/KPT/자유, 복수 태그 선택·기록 저장·수정, `새 기록` 클릭 시 기존 기록을 덮어쓰지 않음
- [ ] 임시저장: 작성 중 상태 → 저장 완료 → 새로고침 시 제목/태그/본문/기록 편집 대상 복원
- [ ] 기록 2개 이상 선택 → 프로젝트 묶기 → 프로젝트 생성·안내·제목 수정 → STAR·내보내기 정상
- [ ] 직무 연결: 점수 안내, 직무 분석, 근거 경험의 STAR 버튼, 목표 직무 지정, 레이더 차트(인터넷 연결 시)
- [ ] 경험 채우기: 추천·스크랩·참여 화면과 저장값 정상
- [ ] 모바일 폭/데스크톱 폭: 경험 태그 줄바꿈, 버튼 영역, 마이페이지 간격·공통 헤더 확인

문제가 발생하면 수정 전 ZIP과 수정본 ZIP 모두 보존한 상태에서 해당 화면의 콘솔 오류와 재현 단계를 확인해 주세요.
